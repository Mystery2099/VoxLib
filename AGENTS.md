# Working with Mathew

## About the developer

Hi! My name is Mathew and I am an application software development college student who works primarily with Java, Kotlin, TypeScript, Python, and C#. I frequently develop Minecraft mods, web applications, command-line tools, and self-hosted software. I LOVE automation and reducing future effort even if I have to put in more effort up front. I HATE peoples creativity being limited.



## Communication

- Explain important architectural decisions, but avoid narrating obvious steps.

- Be direct when an idea is impractical or introduces unnecessary complexity.

- Ask questions only when the missing information materially affects the result.

- Prefer making a reasonable, documented assumption over blocking progress.

- When presenting alternatives, recommend one rather than leaving every choice open.

## Coding Style

- Favor readable, maintainable code over clever abstractions.

- Avoid premature abstraction and unnecessary indirection.

- Use descriptive names.

- Keep functions focused, but do not fragment simple logic too much.

- Follow the existing codebase's style before applying personal defaults.

- Preserve type safety and avoid unchecked casts or broad suppression annotations.

- Add comments for reasoning, constraints, or unusual behavior, not for obvious code.

- Handle errors explicitly and provide useful error messages.

- Avoid adding dependencies unless they provide clear value.

### Java and Kotlin Style



When working with Java or Kotlin, take a lot of inspiration from Vanilla Minecraft's code style and implementation patterns, especially modern Minecraft. Write Java like a true Java developer.

- Prefer straightforward, explicit code over heavily abstracted or overly “enterprise” designs.

- Follow Vanilla-like naming, class organization, control flow, and method structure where practical.

- Look for comparable Vanilla Minecraft code before inventing a new pattern.

- Prefer small helper methods and clear state transitions over complex inheritance hierarchies or excessive indirection.

- Avoid unnecessary interfaces, factories, managers, wrappers, and dependency injection.

- Keep behavior close to the classes and objects it belongs to.

- Use existing Minecraft concepts and APIs naturally instead of building parallel abstractions around them.

- When modifying Minecraft behavior, mirror Vanilla's implementation as closely as practical and change only what is necessary.

- Preserve the existing repository's conventions when they intentionally differ from Vanilla.

For Kotlin:

- Retain the overall simplicity and structure of Vanilla Java code.

- Use Kotlin features when they improve clarity, safety, or reduce genuine boilerplate.

- Do not make code excessively functional, DSL-heavy, or “clever” merely because Kotlin permits it.

- Avoid forcing Java patterns that are unnatural or unsafe in Kotlin.

## Preferences 

- Prefer open-source and cross-platform solutions.

- Maintain Linux compatibility unless a project explicitly targets another platform.

- For web development, my usual preferences are TypeScript, Svelte/SvelteKit, Tailwind CSS, and Lucide icons.

- For Minecraft modding, I generally prefer Kotlin and data-driven designs.

- Optimize for good performance, but do not sacrifice maintainability for tiny gains.
